## Component API

### Initialization

```js
import { dateRangePickerInit } from '@uswds-tailwind/compat/date-range-picker'

dateRangePickerInit()
```

The initializer returns an array of instances and reuses existing instances. For one picker, use `DateRangePicker.getOrCreateInstance(elementOrSelector, options)`.

### Anatomy

Use `data-scope="date-range-picker" data-part="root"` on the root. Both inputs use `data-part="input"`; both calendar buttons use `data-part="trigger"`. Their DOM order determines the endpoint: the first input and trigger edit the start, and the second input and trigger edit the end. No `data-target` attribute is needed.

Both endpoints share one `content` element and one `status` region. Keep the day, month, and year `view` elements and complete calendar templates from the example. The calendar uses the same short part names and navigation attributes as [Date Picker](/docs/vanilla/components/date-picker#component-api).

### Configuration

The wrapper always uses range selection. Constructor options take precedence over authored HTML. Attributes are read during construction; later changes do not reconfigure the instance.

<ApiTable label="Date range picker configuration">

| HTML source | Constructor option | Behavior |
| --- | --- | --- |
| Root `data-min-date`, `data-max-date` | `min: Date`, `max: Date` | Date bounds. HTML uses ISO `YYYY-MM-DD`. |
| Input `value` | `defaultValue: (Date \| undefined)[]` | Initial endpoints. HTML values use `MM/DD/YYYY`; constructor values use Date objects, with start at index 0 and end at index 1. |
| Root or either input `disabled` | `disabled: boolean` | Disables both endpoints and the calendar. |
| Root or either input `readonly` | `readOnly: boolean` | Prevents input and calendar editing. |
| Each input `name` | None for separate names | Each visible field keeps its authored form name. |
| `<html lang>` | `locale: string` | Locale for month and weekday labels. Uses English if `<html lang>` is unset. |

</ApiTable>

Selecting a date closes the calendar without advancing to the other endpoint. Open the other trigger to edit that endpoint. `onValueChange` receives endpoint slots in `value` and ISO strings in `valueAsString`; missing dates remain `undefined` and empty strings respectively.

### Accessibility and lifecycle

Give each endpoint a distinct visible label, form name, and format hint. The start cannot follow the end; the end cannot precede the start. Root bounds further limit both endpoints.

Retain the root element because initialization changes generated IDs. Use the shared element-based `getInstance()` and call `destroy()` before removing the markup. See [instance lifecycle](/docs/vanilla/javascript#instance-lifecycle).
