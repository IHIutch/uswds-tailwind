## Component API

### Initialization

Run `dropdownInit()` from `@uswds-tailwind/compat/dropdown` after the markup exists, or use the auto initializer described in the [JavaScript guide](/docs/vanilla/javascript).

### Parts

`root` contains `trigger` and `content`. Each `item` belongs inside `content`. The initializer manages expanded state, hides closed content, and returns focus to the trigger after Escape or link activation. Native buttons and links provide keyboard activation and Tab navigation. It does not implement menu roles or arrow-key navigation.


### Configuration and methods

`dropdownInit()` returns initialized instances. Use `Dropdown.getOrCreateInstance(root, options)` before convenience initialization to pass `id`, `ids`, or `onItemSelect`.

Each item may have a nonempty `data-value`, with its `id` as a fallback. The initializer attaches activation handlers to links inside items. `onItemSelect` receives `{ value: string }` when a link with an item value activates. It is a JavaScript callback, not a DOM event.

The component starts closed and does not accept `open`, `defaultOpen`, or `onOpenChange`. `open()` and `close()` return `Promise<void>` after the queued update. `api.open` exposes current state. Call `destroy()` before removing markup. See [instance lifecycle](/docs/vanilla/javascript#instance-lifecycle).

### Accessibility

Provide a meaningful button label and descriptive link text. The runtime generates the trigger's `aria-expanded` and `aria-controls`, and hides closed content. Escape or outside interaction dismisses an open dropdown.
